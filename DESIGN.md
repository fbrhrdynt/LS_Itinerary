# Itinerary design direction

Product: a practical travel-planning workspace for individual and group trips.
Audience: mobile-first Indonesian users who want itinerary and cost planning without spreadsheet overhead.

## Character

- Flat, youthful, and specific to travel planning.
- Light blue is the single product accent; deep navy anchors information.
- The interface should feel like a compact digital travel notebook, not a generic SaaS dashboard.

## Layout

- Put the work first: trips for users, account control for administrators.
- Real metrics stay compact and secondary to the trip list.
- Use tables for comparison, cards only when an item is independently actionable.
- Use status-driven color only where it communicates trip state.
- The trip page may use a flat blue identity block because destination, date, and budget are the primary context for every action below it.
- Mobile is an intentional reflow, not a squeezed desktop page.

## UI

- Flat surfaces. No gradients, glow, glass, or broad shadows.
- Hierarchy comes from type, spacing, border weight, and a small number of solid color blocks.
- Moderate radius: 6–12px for panels and controls; pills only for real tags/status.
- Blue is reserved for primary actions, active navigation, trip context, and meaningful emphasis.
- System UI type stack; no decorative font dependency.
- Avoid uniform card grids. Different content types should use the format that fits the task.

## Copy

- Concise Indonesian.
- Buttons name the action: "Buat trip", "Tambah agenda", "Simpan perubahan".
- Status labels describe real state only.
- No hype, fake statistics, filler sections, or dead controls.

## Motion

MOTION 1: focus, hover, and direct interaction feedback only.
